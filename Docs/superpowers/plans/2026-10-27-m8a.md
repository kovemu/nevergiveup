# M8-A Level Editor Implementation Plan

User's detailed specification authorizes implementation and validation without another design approval round. Use the existing Editor/Scene/Prefab architecture, UI Toolkit and the M7-D actor unchanged.

## Design
Use a dockable EditorWindow, authored scene metadata and prefab instances under Stage/Terrain sections. Sections only scope editing/analysis; runtime remains one map. Avoid a separate file format, procedural runtime generation, model changes or scene regeneration of existing maps. New OnlyUpMain copies the saved ClimbPlaytest setup, replaces only its terrain/goal in the new copy, and contains a small 10-platform sample. Palette assets are new; physics box reuses the existing Box prefab via a variant.

Route visualization reuses PlatformGraph connections and PolicyRoute capsule arc tests with the actual CharacterMotor profile. WALK/SHORT/LONG/blocked and unchecked are distinct; intentional player-help metadata never turns failed geometry into success. Analysis is explicitly requested and bounded per editor update, with section scope for larger maps. A geometrically reachable route is not proof of policy completion.

## Tests
Editor checks cover prefab linkage, Z plane, section parenting, transform undo/redo, duplicate/delete undo, start/goal wiring, native scene round trip, short/long/blocked graph categories, unreachable warning and intentional-help classification. UI operations must also be exercised through the real Scene view; API checks cannot substitute for mouse placement. Play Mode records actual completion separately from editor geometric checks.
