# 2. 프로젝트의 핵심 철학

NeverGiveUp은 플레이어가 캐릭터를 직접 조종하는 게임이 아니다.

얼굴 없는 파란색 클레이 캐릭터가 스스로 정상까지 올라가려 노력하고, 플레이어는 손으로 도와주거나 방해한다.

캐릭터는 다음 특성을 가져야 한다.

- 스스로 주변을 관찰한다.
- 스스로 목표를 선택하고 이동한다.
- 장애물을 만나면 해결 방법을 시도한다.
- 실패하면 그 실패를 기억한다.
- 같은 방법만 무한 반복하지 않는다.
- 다른 접근 위치, 다른 점프, 다른 경로를 탐색한다.
- 물리적으로 떨어지면 실제 떨어진 곳에서 다시 도전한다.
- 도저히 해결되지 않으면 잠시 앉아 쉬어도 된다.
- 하지만 포기하거나 종료하지 않는다.

**실패는 허용하지만, 실패로부터 아무런 행동 변화 없이 같은 시도만 반복하는 것은 개선해야 한다.**

이번 작업의 목적은 완벽한 AI가 아니라, 자율적인 문제 해결 과정이 관찰되는 AI다.

# 3. 현재 문제 분석

현재 M7-D에서 기본 등반 능력과 걷기 우선 행동은 크게 개선되었다.

그러나 실제 게임에서는 다음 문제가 관찰된다.

1. 같은 발판에서 같은 점프를 반복한다.
2. 같은 장애물에 계속 충돌한다.
3. 접근 위치를 바꾸면 성공 가능한데 바꾸지 않는다.
4. 다른 경로가 보이는데도 선택하지 않는다.
5. 실패 후 잠시 쉬지만, 일어난 다음 같은 실패를 반복한다.
6. 플레이어 눈에는 스스로 판단하지 않는 캐릭터처럼 보인다.

이 원인을 반드시 실제 코드와 런타임 로그에서 분석하라.

현재 확인된 주요 구조적 한계:

### A. PPO 모델은 고정되어 있다

현재 ONNX 모델은 추론 전용이며 게임 도중 가중치가 업데이트되지 않는다.

42개 관측을 입력받아 좌우 이동과 SHORT/LONG 점프 결정을 출력한다.

따라서 같은 상황에서는 비슷한 행동을 반복할 수 있다.

### B. 실패 기억이 너무 단기적이다

현재 `PolicyActionCorrection`은 같은 발판·목표·점프 종류·도약 위치 근처에서 실패한 시도를 기록하고, 반복 실패 시 약 4초간 제한한다.

이것은 전략 학습이 아니라 일시적인 배제에 가깝다.

### C. 행동 교정 계층은 대안 전략을 직접 만들지 않는다

현재 구현은 모델이 요청한 방향과 점프를 검사하고 일부 제한하지만, PPO가 제안하지 않은 새로운 접근 방향이나 경로를 적극적으로 탐색하지 않는다.

따라서 물리적으로 가능한 우회로가 존재해도 실행하지 못할 수 있다.

### D. 휴식은 전략 변경과 연결되어 있지 않다

막힘이 누적되면 SitDown/Rest/GetUpFromSit은 발생할 수 있지만, 휴식 이후 새로운 전략이 반드시 선택되는 것은 아니다.

이러한 한계를 해결하되, 무작정 조건문을 추가하는 방식으로 끝내지 마라.

# 4. M8-B의 목표 아키텍처

기존 AI를 폐기하거나 Legacy AI로 교체하지 않는다.

다음 세 계층으로 역할을 분리한다.

## 4.1 상위 계층 — 자율 전략 판단

새로운 전략 판단 시스템을 추가한다.

가칭:

`AutonomousStrategyPlanner`

담당 역할:

- 현재 발판과 목표 확인
- 주변에서 도달 가능한 발판 후보 탐색
- 가능한 접근 위치 비교
- WALK / SHORT / LONG 후보 비교
- 성공 및 실패 경험 반영
- 반복 실패한 전략의 우선순위 감소
- 대체 경로 선택
- 주변 물리 환경이 바뀌면 전략 재평가
- 잠시 쉬었다가 다른 방법으로 재시도

## 4.2 중간 계층 — 기존 M7-D 행동 교정

`PolicyActionCorrection`의 기존 기능을 재사용한다.

- 위험한 점프 차단
- 불필요한 점프 방지
- 실제 캡슐 궤적 검증
- 발판 접근 위치 검사
- 안전한 WALK 판단
- SHORT/LONG 도달성 확인

전략 판단 계층이 선택한 후보도 실제 물리 검사에서 불가능하면 실행해서는 안 된다.

## 4.3 하위 계층 — PPO 운동 AI

기존 `NGUClimbVertical.onnx`가 운동 제어를 담당한다.

- 걷기
- 방향 전환
- 점프 동작
- 공중 제어
- 착지

상위 계층은 목표 발판, 임시 목표, 접근 조건 또는 실행 가능한 행동 범위를 조정할 수 있다.

하지만 모든 프레임의 좌우 입력과 점프를 규칙으로 직접 결정하는 또 하나의 Legacy 컨트롤러를 만들지 마라.

기존 42개 관측 인터페이스와 모델의 입력 범위를 유지한다.

상위 전략을 PPO가 잘 따르지 않는다면 그 한계를 실제 테스트로 확인하고, 최소한의 보조 제어 또는 향후 추가 학습 필요성을 구분해 보고하라.

# 5. 실제 실패 경험 기록

일시적인 쿨다운이 아니라 실제 행동 결과를 기반으로 전략의 가치를 평가하는 메모리를 구현한다.

가칭:

`StrategyExperienceMemory`

각 시도에는 최소한 다음을 기록한다.

- 출발 발판 ID
- 목표 발판 ID
- 지형 또는 환경 버전
- 출발 X 좌표
- 접근 방향
- 선택한 행동(WALK/SHORT/LONG)
- 목표 착지 위치
- 실제 도약 위치
- 실제 착지 위치
- 충돌 여부와 충돌 대상
- 성공 여부
- 상승한 높이
- 목표에 가까워진 거리
- 플레이어 개입 여부
- 시도한 전략 식별자
- 해당 전략의 누적 시도 횟수
- 성공·실패 횟수

단순히 특정 점프를 실패로 처리하는 것이 아니라 왜 실패했는지 가능한 범위에서 분류한다.

예시:

- Shortfall: 거리가 부족함
- Overshoot: 지나침
- CeilingCollision: 위쪽 충돌
- SideCollision: 측면 충돌
- UnsafeLanding: 안정적으로 착지하지 못함
- RepeatedNoProgress: 동일 시도 반복, 진전 없음
- EnvironmentChanged: 장애물이나 발판이 변함
- PlayerInterference: 플레이어가 물리적으로 개입함
- Unknown: 증거가 부족함

판정 근거가 없는 실패 원인을 추측해서 기록하지 마라.

플레이어가 때리거나 상자를 움직여 발생한 결과는 AI 자신의 순수한 실패로 학습하지 않는다.

# 6. 실패 후 다른 전략 탐색

이번 작업의 가장 중요한 요구사항이다.

## 6.1 동일 실패 반복 감지

동일한 출발 발판, 목표 발판, 비슷한 도약 위치와 점프 종류에서 반복 실패가 확인되면 해당 전략의 선호도를 낮춘다.

시간이 지나면 아무 기록도 없는 것처럼 초기화되는 방식은 피한다.

다만 실패한 전략이 유일한 가능 경로라면 완전히 영구 차단하지 않는다.

## 6.2 대체 행동 후보 생성

다음 후보를 가능한 범위에서 실제 물리 검사로 생성한다.

- 더 왼쪽 접근 위치
- 더 오른쪽 접근 위치
- SHORT 점프
- LONG 점프
- 더 넓은 안전 발판으로 우회
- 다른 인접 발판으로 이동
- 기존 경로를 잠시 벗어나는 경로
- 현재 장애물에서 뒤로 물러나 다시 접근

각 후보는 기존 `PlatformGraph`, `PolicyRoute`, `CharacterMotor`의 도달성 검사와 충돌 검사를 사용한다.

현재 위치에서 점프가 불가능하더라도 다른 위치로 걸어간 뒤 점프 가능한지 확인한다.

다른 방향으로 돌아가는 경로가 유효하다면 필요할 때 후퇴도 허용한다.

## 6.3 후보 평가

다음 요소를 함께 고려한다.

- 물리적 도달 가능성
- 이전 성공 경험
- 이전 실패 횟수
- 현재 위치에서의 접근 난도
- 목표 높이와의 관계
- 추락 위험
- 동일 전략 반복 여부
- 새로운 전략 탐색 가치

높은 곳으로 올라가는 행동을 선호하되, 일시적으로 아래로 내려가거나 뒤로 이동해야 하는 우회로도 허용한다.

지금까지 가장 높은 곳에 도달한 기록만 기준으로 모든 결정을 내려서는 안 된다.

## 6.4 새로운 시도의 실제 실행

새로운 전략을 선택했다면 캐릭터가 실제로 다르게 행동하는지 확인한다.

예를 들어:

기존 전략:
발판 오른쪽에서 LONG 점프 → 측면 충돌 → 같은 지점에서 반복

변경 전략:
발판 왼쪽으로 이동 → 도약 방향 전환 → SHORT 또는 LONG 실행

또는:

기존 전략:
정면 발판만 반복 도전

변경 전략:
뒤쪽의 낮은 발판으로 이동 → 다른 경로로 정상 접근

전략 이름만 바뀌고 실제 Rigidbody의 움직임이 같다면 실패로 간주한다.

# 7. 장기 기억과 학습

새로운 전략 메모리는 하나의 실행 세션 안에서 유지해야 한다.

일부 전략을 반복해서 성공했다면 비슷한 상황에서 그 전략의 우선순위가 높아져야 한다.

반복 실패한 전략은 상황이 그대로라면 우선순위가 낮아져야 한다.

다만 다음을 지켜라.

- 모델 ONNX 가중치를 직접 수정하지 않는다.
- M3 Legacy `LearningMemory`와 Learned 메모리를 혼동하지 않는다.
- 기존 저장 데이터를 파괴하지 않는다.
- 지형 변경 시 더 이상 유효하지 않은 경험을 무분별하게 재사용하지 않는다.
- 기록 크기와 전략 수는 적절히 제한한다.
- 저장된 기억을 초기화할 수 있는 개발자 기능을 제공한다.

가능하면 Learned 전용 JSON에 전략 경험을 저장하고 다음 실행에서 불러올 수 있도록 한다.

단, 테스트용 임시 기억과 실제 플레이용 지속 기억을 구분한다.

지속 기억 기능 때문에 기존 AI 동작이 불안정해지면 우선 세션 내 학습부터 안정화하라.

# 8. 휴식과 전략 변경 연동

현재의 자발적 휴식은 유지한다.

하지만 같은 행동을 반복하다 앉았다가 일어난 뒤, 무조건 같은 시도로 복귀해서는 안 된다.

휴식 전에 실패했던 전략을 확인한다.

가능한 대안이 있다면 휴식 후 다른 전략을 선택하도록 한다.

가능한 대안이 없다면 주변을 다시 관찰하고 물리적으로 가능한 범위에서 새로운 접근을 검토한다.

정말로 갈 수 있는 경로가 없는 경우에는 플레이어 개입을 기다리거나 간헐적으로 재도전할 수 있다.

**절대 포기하거나 강제로 리스폰하지 않는다.**

기존 Learned → Legacy 자동 전환 제거 규칙을 유지한다.

# 9. 플레이어가 지형을 바꾸는 상황

플레이어가 상자를 움직이는 것은 NeverGiveUp의 중요한 게임플레이 요소다.

다음 상황을 구현·검증한다.

1. AI가 상자 때문에 경로를 찾지 못한다.
2. AI가 제한된 횟수로 장애물 주변을 탐색한다.
3. 실패 경험을 누적하고 필요하다면 잠시 쉰다.
4. 플레이어가 상자를 이동한다.
5. AI가 변경된 경로를 인식한다.
6. 이전에 실패한 전략을 무조건 반복하는 대신 새로 열린 경로를 평가한다.
7. 가능한 경로를 찾아 자발적으로 다시 상승한다.

단, 플레이어가 상자를 잡고 있다는 이유만으로 외부 개입이 발생했다고 판단하지 마라.

M7-D에서 수정한 '정지한 채 잡고 있는 상자'와 '실제로 움직인 상자'의 구분을 유지한다.

AI가 아직 관찰할 수 없는 먼 장애물을 전지적으로 알고 반응하는 행동도 피한다.

# 10. AI가 자율적으로 보이게 만드는 기준

성공률만으로 이번 작업의 성패를 판단하지 않는다.

다음 행동이 실제로 보여야 한다.

### A. 재평가

실패 후 같은 도약 위치만 고집하지 않는다.

### B. 탐색

가능한 다른 발판이나 접근 위치를 시도한다.

### C. 전략 변경

SHORT가 실패하면 LONG 또는 다른 위치를 검토하고, LONG이 실패하면 SHORT·접근 위치·다른 경로를 검토한다.

SHORT/LONG을 무작정 교대로 사용하는 것은 전략 변경으로 인정하지 않는다.

### D. 성공 경험 활용

성공한 접근법을 비슷한 상황에서 재사용한다.

### E. 물리적 실패와 재도전

떨어지면 실제 착지한 발판에서 현재 상황을 다시 판단한다.

### F. 서툰 개성 유지

모든 행동을 최적화하여 완벽하게 움직일 필요는 없다.

때로는 망설이고, 실패하고, 쉬어도 된다.

다만 같은 실패를 의미 없이 반복하는 상황은 줄여야 한다.

# 12. 필수 실제 테스트

## 테스트 A — 동일 점프 반복

같은 위치에서 같은 점프를 두 번 실패하도록 구성한다.

그 후 AI가 다음 중 하나 이상의 실질적인 변화를 시도하는지 확인한다.

- 도약 위치 변경
- 점프 종류 변경
- 접근 방향 변경
- 다른 발판 선택

단순히 4초 기다린 뒤 같은 점프를 반복하는 것은 실패다.

## 테스트 B — 대체 경로 존재

정면 경로는 막혀 있지만 뒤쪽 발판을 거치면 올라갈 수 있는 지형을 만든다.

AI가 실패 후 실제로 뒤로 이동하거나 다른 발판으로 우회하는지 확인한다.

경로 후보가 존재한다는 디버그 표시만으로 통과 처리하지 않는다.

실제 Rigidbody 이동을 확인한다.

## 테스트 C — SHORT/LONG 선택

SHORT가 가능한 낮은 발판과 LONG이 필요한 높은 발판을 배치한다.

접근 위치에 따라 적절한 점프를 선택하는지 확인한다.

## 테스트 D — 완전히 막힌 상황

플레이어가 움직일 수 있는 상자로 필수 경로를 막는다.

AI가 반복 실패 후 쉬거나 다른 방법을 검토하되 무한한 동일 궤적 반복을 줄이는지 확인한다.

Legacy 전환, 순간이동, 강제 초기화는 금지한다.

## 테스트 E — 플레이어의 구조

막혀 있던 상자를 플레이어가 옮기면 AI가 새로 열린 경로를 인식하고 다시 도전하는지 확인한다.

## 테스트 F — 추락 후 재계획

높은 발판에서 추락해 이전 구역으로 떨어진 뒤, 기존 목표를 향해 새로운 경로를 선택하는지 검증한다.

## 테스트 G — 새로운 지형

기존 학습 평가에 없던 서로 다른 2~3개 지형에서도 테스트한다.

익숙한 16층 패턴만 성공하는 것은 충분하지 않다.

# 13. 성능 비교

M7-D 기존 성능을 기준으로 회귀 검증한다.

M7-D 평가 기록:

| 환경 | 성공 |
| --- | --- |
| 평지 | 65/65 |
| 6층 | 64/64 |
| 11층 | 65/65 |
| 16층 | 64/64 |

위 수치는 특정 평가 설정의 결과이며 보편적 성공률이 아니다.

기존 결과와 같은 조건에서 비교 평가한다.

그리고 별도의 신규 지형 테스트를 진행한다.

최소한 다음 지표를 비교하라.

- 완주율
- 평균 도달 높이
- 평균 완주 시간
- 실제 걷기 거리
- SHORT/LONG 사용 횟수
- 동일 위치 반복 실패 횟수
- 전략 변경 횟수
- 전략 변경 후 실제 성공 횟수
- 대체 경로 발견 비율
- 휴식 후 동일 실패 반복 비율
- 플레이어 환경 변경 후 재개 시간

**가장 중요한 평가는 동일한 문제에서 이전과 다른 해결 방법을 실제로 찾아 시도했는가다.**

모든 후보를 하나씩 강제 실행해서 결국 성공시키는 가짜 자율성을 만들지 마라.

상위 전략과 PPO의 실제 제어를 구분해 검증한다.

# 16. 완료 기준

이번 작업은 단순히 새 클래스가 추가되거나 자동 테스트가 통과했다고 끝나는 작업이 아니다.

다음 조건을 만족해야 한다.

1. 같은 실패를 반복한 뒤 의미 있게 다른 전략을 시도한다.
2. 새로운 전략이 실제 캐릭터 이동에 반영된다.
3. 가능한 우회 경로가 있으면 적어도 테스트 지형에서는 이를 발견하고 사용한다.
4. 실패 경험이 다음 판단에 영향을 준다.
5. 성공 경험이 다음 전략 선택에 영향을 준다.
6. 상자 이동 후 새로운 경로를 다시 평가한다.
7. 추락 후 실제 위치에서 재계획한다.
8. 기존 기본 등반 능력이 크게 저하되지 않는다.
9. Learned AI의 운동 제어권을 유지한다.
10. Unity 실기 검증과 Windows 빌드가 성공한다.
